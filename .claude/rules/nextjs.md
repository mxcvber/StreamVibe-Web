# Next.js 16

Next 16.3.4 with React 19.2.8 contradicts Next 14/15 habits. When unsure about an API, read
`node_modules/next/dist/docs/` rather than recalling it (upgrade notes:
`01-app/02-guides/upgrading/version-16.md`).

## Changed APIs

- `params`, `searchParams`, `cookies()`, `headers()` and `draftMode()` are Promise-only.
- `PageProps<'/route'>`, `LayoutProps<'/'>` and `RouteContext<'/route'>` are global, generated by
  `next dev`, `next build` or `npx next typegen`. Don't import them.
- `middleware` is now `proxy.ts` exporting `proxy`, on the `nodejs` runtime only (`edge` is
  unsupported). `skipMiddlewareUrlNormalize` is `skipProxyUrlNormalize`. Relevant once auth lands.
- Turbopack is the default: don't add `--turbopack`, and a custom `webpack` config makes
  `next build` fail. `experimental.turbopack` is top-level `turbopack: {}`.
- `revalidateTag(tag, profile)` needs both arguments. `cacheLife`, `cacheTag`, `updateTag()` and
  `refresh()` are stable imports from `next/cache`.
- next/image: `priority` is deprecated (the docs prefer `loading='eager'` to its replacement,
  `preload`), `minimumCacheTTL` is 4 hours, and `remotePatterns` replaces `domains`
  (`image.tmdb.org` is already allowed). `images.qualities` defaults to `[75]`; ours is
  `[50, 75, 100]`, and `PosterMosaic`'s `quality` type mirrors it.
- Parallel routes need a `default.js` per slot. AMP, `serverRuntimeConfig`,
  `publicRuntimeConfig` and `experimental.ppr` are gone. Smooth scrolling on navigation needs
  `data-scroll-behavior="smooth"` on `<html>`. Node >= 20.9.

## Cache Components (`cacheComponents: true`)

- `fetch` is uncached and blocks render: cache it with `'use cache'` or wrap it in `<Suspense>`.
- The `dynamic`, `revalidate`, `fetchCache` and `dynamicParams` segment exports don't exist.
- An unstable value such as `new Date()` fails the prerender unless it is cached
  (`CopyrightYear` uses `'use cache'` + `cacheLife('days')`).
- A dynamic route's `generateStaticParams` must return at least one param; `[]` is a build
  error. It covers only its own page, so `genres/[slug]/top-10` repeats the `[slug]` page's
  (the docs also allow declaring it once in a shared `[slug]/layout.tsx`).
- `MainNav` and `MobileNav` call `usePathname()` outside `<Suspense>`. A dynamic route without
  `generateStaticParams` therefore fails the build, and dev reports
  `blocking-prerender-client-hook` for every param it doesn't list. `/movies/[id]` can't list
  its ids, so it returns one known id (19995) and exports `instant = false`, which only relaxes
  dev-time validation. A new `[param]` route needs the same until the navs are wrapped in
  `<Suspense>`, which is still undecided (`.claude/docs/state.md`).
- A layout that sets `title` must repeat `template` (`MoviesLayout`): a plain string drops the
  root layout's template for every page below it.

## Dev-only quirks

- `next.config.ts` sets `minimumCacheTTL: 60` in dev only. The dev image cache is keyed by URL,
  not contents, and placeholder images get swapped by hand under the same names.
- A Tailwind class used only in a brand-new route directory can be missing from the dev CSS
  until the file is touched. Check `document.styleSheets` before debugging the layout;
  `next build` is the source of truth.
